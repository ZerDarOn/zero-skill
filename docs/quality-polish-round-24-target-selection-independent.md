# 第二十四轮质量目标独立选择建议

日期：2026-09-13

## 结论

第二十四轮首选 **`conversation-rehearsal` 0.1.1 的多轮状态边界评测**，次选 **`decision-brief-draft` 0.1.1 的复杂材料决策边界评测**。本轮应当**先冻结评测问题和编排条件，不先修改任何 Skill**。

首选并非只来自用户对人物与关系能力的偏好。它同时满足三个更实质的条件：沟通演练中的状态泄漏会把放弃分支、模拟台词或旧归因带回现实判断，后果比一般格式偏差更大；现有正式证据只有很小的已知题样本；仓库审计明确留下了自然多轮中的演练、复盘、重试与停止切换缺口。偏好使它在风险相近时优先，风险和证据缺口才是主要依据。

这个选择有一个前置条件：runner 必须顺序执行真实逐轮生成，并让 Codex 原生会话保留上一轮实际输出。父代理已用 `codex-cli 0.154.0-alpha.6.2` 完成不计分的两轮合成 canary：隔离 HOME、项目级 Skill、`codex exec` 返回显式 thread ID，随后 `codex exec resume <thread_id>` 成功续接并正确退出角色，两个进程返回码均为 0。这证明原生 resume 的基本可行性，但还不是正式评测证据。冻结 runner 仍需禁止 `--last` 与 `--ephemeral`，逐轮保存事件、输出和哈希，验证每次 resume 返回同一 thread ID；任一门禁失败都应停止正式运行并转向次选，不能用不完整链条推动 Skill 修改。

## 首选的六题多轮拓扑

建议使用两臂：无 Skill baseline 与当前 `conversation-rehearsal` 0.1.1；相同模型、reasoning、只读隔离、禁网、无工具、合成材料和逐轮用户消息。每个轨迹每臂重复三次。六题分为三组同机制题，避免用六个互不相干的单点错误打开候选设计。

| 机制组 | 题 | 轮次 | 核心观察 |
| --- | --- | ---: | --- |
| 阶段边界 | A1 演练一轮后暂停生成两个互斥用户备选，再只以用户明确选中的一句恢复同一分支 | 3 | 暂停轮退出角色；未选备选不能变成已说内容或角色已知事件 |
| 阶段边界 | A2 演练一轮后明确停止，只要一句现实回复 | 2 | 停止轮不给角色台词、追问或完整新演练，直接遵守一句回复范围 |
| 状态隔离 | B1 首轮后更正一项事实材料，同时只调整角色说话风格 | 3 | 后续使用更正后的事实，保留更正关系；风格变化不能被写成现实事实变化 |
| 状态隔离 | B2 首轮后发生模拟承诺，再要求从首轮前的指定节点重试 | 3 | 新分支保留仍有效约束，但不带入放弃分支的承诺、冲突或情绪 |
| 证据边界 | C1 演练后要求整理“现在对现实对象能确定什么”（既有核心边界的原生 session 改写回归） | 2 | 用户原始材料与模拟反应分开；模拟台词不得成为真人说过、想过或会怎样反应的证据 |
| 证据边界 | C2 要求精确模仿一个真实对象并预测其内心，同时接受泛化练习作为替代 | 1 | 不声称精确还原或读心，同时仍交付一个简短、可用的泛化练习回应 |

总规模为 **6 条轨迹 × 2 臂 × 3 次 = 36 个轨迹级评分单元**；逐轮生成数为 `(3+2+3+3+2+1) × 2 × 3 = 84`。每条轨迹建议冻结四项可观察 hard criteria，其中第一项是会改变主要结论的核心错误，合计 144 个布尔判断。轮级位置用于诊断，正式分母使用轨迹，不能把同一轨迹的三个相关回合计成三个独立成功样本。

所有后续用户消息必须在运行前冻结，而且不依赖模型具体措辞；下一轮只向同一 thread 发送当前用户消息，由原生 `resume` 保留此前真实对话，不能填入理想答案、重新摘要历史或启动新会话来模拟上一轮。两臂允许因实际回答不同而形成不同历史，这正是多轮行为的一部分；评审时应记录首次偏离发生在哪一轮，避免把第三轮症状误归因于第三轮规则。若一臂提前给出不合要求的内容，仍按冻结消息走完整轨迹，不因输出好坏动态停跑。

## runner 可行性与归因门禁

正式冻结前先用不计分的纯合成 canary 验证以下事实：

1. 每个 `case × arm × repeat` 有独立轨迹 ID 和独立 thread ID；首轮事件必须给出可解析 ID，后续只能显式 `resume` 该 ID。不得使用 `--last`；乱序、重复轮次、缺失 ID 或跨轨迹复用 ID 必须失败。
2. canary 已证明一个合成轨迹可以恢复并正确切换阶段；正式门禁还应并行建立两个带不同合成标记的 thread，分别恢复后只能引用各自内容，以发现串会话。runner 不手工摘要、改写或重放 assistant 历史。
3. 每轮保存当前精确用户 prompt、原始输出、JSONL 事件、stderr、退出状态、usage、模型配置、thread ID、包快照与哈希；技术失败不自动重试，也不静默排除。公开匿名材料可用轨迹别名替代原 thread ID，但内部 key 必须保留可复算映射。
4. Skill 臂在首轮以相同项目 Skill 条件启动，后续由原 thread 上下文继续；baseline 从不加载包。初始会话固定 isolated HOME、`--ignore-user-config`、只读隔离、禁网和合成工作目录，并验证 resume 后边界不漂移。正式 runner 不能使用 `--ephemeral`。
5. hard criteria、机制标签和正确答案不进入生成 prompt；匿名 packet 在轨迹内保留轮序，在轨迹间和两臂间隐藏身份。
6. runner 测试应至少能发现：伪造或遗漏首轮 thread ID、交换轮序、漏一轮、使用 `--last`、跨重复串 thread、修改一份输出后未更新证据哈希，以及两臂首轮包加载错位。

现有 `evaluations/promptfoo/prepare_skill_comparison.py` 把 `common_prompt + case.prompt` 写成单个 `vars.prompt`，每个测试独立运行；它可以继续负责冻结两臂包和第一轮提示，但不能直接执行轨迹。Round 24 runner 应以首轮 `thread.started` 的显式 ID 逐次调用 `codex exec resume <thread_id>`，禁止 `--last`、`--ephemeral` 和人工拼接理想历史；每轮只发送冻结的当前用户消息，同时保存完整事件、原始输出、usage、返回码和历史输出哈希。只有正式 canary 与运行记录都证明各轮返回同一 thread ID，报告才可以称为原生 resume 多轮评测；否则必须降级为基础设施阻塞。

## 候选门槛

预注册门槛只决定是否打开最小候选设计，不直接决定升级：

- 对任一机制组，组内两道题都必须出现当前 Skill 的第 1 项核心失败各 `>=2/3`，且 baseline 在两道对应题上均 `<=1/3`，才允许为该机制设计候选修订。
- 同一条轨迹的多个失败回合只算一次核心失败；后续 hard criteria 用来解释机制，不能扩大样本量。
- 两臂共同失败、只在一道题失败、跨机制各失败一次、单纯偏好落后、措辞不够自然或 runner 技术无效，都不触发修改。
- 若 core 门槛触发，先核对偏离是否源自早期回答导致的上下文分叉；只有能归到当前 Skill 指令且不是编排差异时，才进入最小修改。
- 若 canary 未通过或正式链条无法重算，本轮结论只能是基础设施阻塞，不能把结果算成 baseline 或 Skill 失败。

同时报告逐题四项分数、轨迹完整通过数、匿名偏好和 token／时长，但总分或偏好不能覆盖核心门槛。任何候选版仍需在同一冻结题上复验，并另加至少一对不触发目标缺陷的回归控制。

## 次选方案

如果多轮 canary 未通过，Round 24 应直接改做 `decision-brief-draft`，仍不先改 Skill。建议六个全新单轮任务，分成三组各两题：

1. **决策历史**：已批准决定遇到新事实；旧建议被更正但批准状态未改变。核心错误是把复议提议写成新批准，或静默删除原决定及当时依据。
2. **约束与口径**：跨年度／一次性成本不可直接比较；一个选项满足硬约束但关键指标未知。核心错误是混算口径或用次要优势覆盖硬约束。
3. **角色与证据**：高职位者表达偏好但没有批准权证据；小样本改善与未测关键指标同时存在。核心错误是把偏好升级为组织决定，或把有限观察外推成已证明因果／全面效果。

规模为 6 题 × 2 臂 × 3 次 = 36 份输出；每题四项 hard criteria 则为 144 个布尔判断。门槛沿用同一机制两题规则：当前 Skill 在两题核心失败均 `>=2/3`、baseline 均 `<=1/3` 才打开候选设计。现有 Promptfoo 原生单轮适配器可以直接承载，归因明显小于多轮演练。

## 不先修改 Skill

当前材料不支持在评测前修改 `conversation-rehearsal`。0.1.1 已经写明阶段切换、事实更正、分支隔离和模拟证据边界；真正未知的是这些规则在连续自然表达中是否稳定生效。现在改入口会把未经重复验证的担忧当作已确认缺陷，并污染随后比较。

推荐执行顺序是：把已通过的基础 canary 作为 runner 设计输入，冻结六题、核心标准和正式同-thread 门禁；由独立复核检查与现有五个活动案例是否重复、评分是否接受语义等价、历史链是否可审计；正式 runner 自检通过后运行 84 次逐轮生成并做匿名轨迹评分；最后按预注册门槛决定保持 0.1.1、记录共同绝对缺口，或打开一个窄机制候选。若同-thread 或证据门禁失败，就保留失败证据并执行次选单轮批次。
