# 第十八轮揭盲后决策独立复核

日期：2026-09-11
复核对象：`claim-evidence-review` 0.1.0 与 `claim-evidence-forward-11` 冻结前向对照

## 决策

**保持 `claim-evidence-review` 0.1.0；本轮不进入 0.1.1 候选设计。建议把六个冻结任务完整保留为回归集，并在新的前向拓扑中复测“多批样本的精确数字保真”，达到跨题、跨重复的机制性门槛后再考虑最小修订。**

本轮显示当前 Skill 没有明显退化，并在部分更正、有限日志等场景中更常得到盲评偏好；但它没有取得硬标准净增益，也没有出现只属于 Skill 臂、跨多个题型稳定复现的共同缺陷。现在升版会违背冻结协议中“不预设升版”和“不从本批答案反写固定模板”的约束。

## Findings

### [P1] 没有达到 0.1.1 的预设机制门槛

- 正式盲评中，两臂都是 `52/54` 个标准通过、`16/18` 个输出完整，硬标准净差为零。
- 冻结前门槛要求“跨题、跨重复的稳定机制性失败”才设计候选（`target-selection-review-independent.md:10`），并要求同一机制在多个新拓扑或重复中稳定失败后才做最小规则修订（同文件 `:73`）。
- Skill 臂的两次失败都集中在 `shared-data-with-new-analysis` 同一个题型、同一条标准：未在最终输出中完整保留两批精确变化。该机制跨重复出现，但没有跨题出现；baseline 也在同题第三次出现相同遗漏。因此它是值得保留的风险信号，还不是可归因于 Skill 的跨拓扑稳定缺陷。
- 当前 0.1.0 已明确要求“保留分母、样本、日期、比较组、否定、概率和不确定性”（`skills/research/claim-evidence-review/SKILL.md:22`）。直接再追加针对 `9/30 → 6/30` 与 `5/20 → 4/20` 的规则，最可能形成题面级重复或强制冗长，而不是补上新的通用机制。

要求：不要据此轮答案修改 Skill。先用至少两个表面不同的新拓扑复测，例如“两个队列加一个共享复核”和“多个地区加部分缺失分母”；只有 0.1.0 在多个新拓扑中仍重复漏掉独立样本的核心定量结果，才设计通用且最小的 0.1.1 候选。

### [P1] 偏好优势不足以抵消硬分持平与成本上升

| 指标 | baseline | ours | 差异 |
| --- | ---: | ---: | ---: |
| 硬标准 | 52/54 | 52/54 | 持平 |
| 完整输出 | 16/18 | 16/18 | 持平 |
| 盲评偏好 | 3 | 7 | ours +4；另有 8 次无偏好 |
| 总 token | 177,055 | 229,099 | ours +52,044，约 +29.4% |
| completion token | 3,387 | 7,053 | ours 约 +108.2% |
| 记录成本 | 0.2942392 | 0.4514008 | ours 约 +53.4% |
| 中位延迟 | 10,227.5 ms | 12,242.0 ms | ours 约 +19.7% |

ours 的 7 次偏好主要来自 `scoped-absence-in-limited-log` 的 3 次、`metric-scoped-correction` 的 2 次，以及另外两个题型各 1 次。这说明 Skill 可能改善边界表达和事故措辞，但偏好是次级、样本量很小的信号；它不能替代硬标准净改善。与此同时，completion token 翻倍，说明较高偏好至少部分可能来自更完整或更长的回答，也带来明显成本。

要求：保持 0.1.0，不以偏好计数单独触发升版。后续若评估表达收益，应预先冻结长度或信息密度标准，避免把“更长”误判为“更好”。

### [P2] 两类失败的决策含义不同，不应合并成一次 Skill 修订

`metric-scoped-correction` 中，baseline 第一次把描述性前后变化写成“新版降低了错误率”，使第三条标准失败；ours 三次全部通过，并在该题获得 2 次偏好、1 次无偏好。这与 0.1.0 关于“前后变化只支持描述性差异、多个条件同时改变时不单独归因”的既有规则一致，是当前规则可能有效的一条正向信号，不是新版本缺口。

`shared-data-with-new-analysis` 中，ours 在第二、三次漏掉至少一批精确数字，baseline 只在第三次出现同类遗漏；该题 ours 为 `7/9`、baseline 为 `8/9`。这暴露的是多批材料压缩时的数值保真风险，而不是来源独立性或因果校准失败：两臂都正确识别两批样本、S2 的复核价值，并避免“三项独立研究”“复制成功”或因果升级。

要求：六题全部进入回归，不只保留失败题。尤其保留随机对照正向控制，防止未来为了避免因果越界而把充分证据一律降格；保留构成反转、嵌入指令和有限日志题，防止针对数字保真修订时引入冗长、机械列举或过度保守。

### [P2] 运行证据有效，但不能证明模型实际读取了 Skill 正文

`summary.json` 记录 36 个计划输出全部执行、两臂均无 provider error、无禁止工具调用，基础设施状态为有效；盲评包、映射和评分结果也能闭合到 18 个逐臂输出。与此同时，ours 虽配置为项目级显式调用，汇总仍记录 `rows_with_expected_skill_call: 0`，且没有 `skill_calls` 或 `attempted_skill_calls` 遥测。

这不推翻两臂对照，但应把结论限定为“项目级显式 Skill 条件下的输出差异”，不能进一步声称已由调用遥测证明每次都实际加载或遵循了 Skill 正文。该限制也使“因硬分持平而立即修改正文”的依据更弱。

## 0.1.1 候选的重新开启条件

以下条件至少满足前两项，才建议进入候选设计：

1. 在至少两个未参与本轮设计的新题型中，0.1.0 重复遗漏多个独立样本的核心分子、分母或前后值；
2. 同条件 baseline 明显更少出现该错误，或旧版/候选/基线三臂对照能把改善归因到候选规则；
3. 候选使用通用检查步骤而不是复述本轮数字，并通过六题完整回归；
4. 候选没有进一步扩大 completion token、延迟或机械化输出，或者质量收益足以解释成本增加。

在此之前，`shared-data-with-new-analysis` 的结果应登记为“数值保真观察项”，而不是 0.1.0 的已确认机制缺陷。

## 编码修复事件记录

建议如实记录为一次**盲评产物写入与显示兼容事件**，而不是模型输出失败、评分标准变更或重新盲评：

1. 匿名候选的 108 个布尔判断、18 个 `preferred_candidate` 和 reviewer 元数据在揭盲前已经形成；首次交接时目标完成文件缺失，评分器在读取阶段失败，没有产生部分评分。
2. 原评审者随后在仍未读取 key、summary、results、prepared 或评分输出的情况下，把既有匿名判断写到指定完成文件并用 `json.load` 验证。
3. 揭盲评分成功后，中文 notes 在归档链路中出现乱码显示。修复前由 Python 以 UTF-8 读取时，18 条 notes 已是有效中文码点、没有 U+FFFD；因此现有证据不能断言源文件字节已经损坏，更准确的描述是写入、显示或下游读取之间的编码兼容问题。
4. 揭盲后由同一原评审者仅用 `json.dump(..., ensure_ascii=False)`、`encoding='utf-8'` 重序列化 notes。原评审任务按包含 `schema_version`、`comparison_id`、reviewer 与 reviews 的投影计算，修复前后 SHA-256 均为 `9444624d61f587ab6cc6baf42315afbdc14006583cb29db4ccb9d395ff42e48c`；仓库报告另按只包含 reviewer 与无 notes reviews 的紧凑、键排序规范投影计算，修复前后均为 `8c98ddf359148697a0f0d9e8fb7b4fe0022b066a2334f7b3b517a8986efe4261`。两者规范化输入不同，不能互相比较，但都证明各自口径下不可变字段未变。验证仍为 18 reviews、108 个布尔值、18 条非空 notes，且无 U+FFFD。
5. 因 notes 的重序列化发生在揭盲后，报告必须保留这一时间顺序，不能写成“全部文件在揭盲前一次生成成功”。同时可明确：数值判断、偏好和 reviewer 元数据未变，修复没有重新评分；正式归档应引用 `review-result-blind-review-completed-independent-encoding-fixed.json`。

该事件不改变两臂分数，但属于可复现性与审计链瑕疵。若本轮结果用于外部发布或作为升版唯一依据，宜由另一评审者从冻结盲包独立复算；本轮仅用于“保持 0.1.0、扩充回归”的保守决策时，现有披露与哈希校验足够。

## 证据边界

- 本结论来自单一模型 `gpt-5.6-sol`、`medium`、六个合成题、每臂三次的显式项目级对照；不代表联网研究、真实领域材料或隐式路由表现。
- 模型辅助盲评不是独立人工学术评审；偏好计数尤其不应解释成统计显著优势。
- 本次只形成升级决策，不修改 Skill、活动用例或评测标准。六题加入回归仍需后续单独实施和验证。
- 按本次读取范围，没有运行仓库级结构校验或全量单元测试；本次仅新增决策文档，不涉及运行时代码。
