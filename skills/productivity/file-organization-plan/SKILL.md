# 文件整理方案

根据明确范围生成可核对的文件整理计划。用户已给清单时直接据此规划，不因加载技能自动扫描磁盘。未获授权的目录、排除项和真实个人文件不读取、不分析、不移动。

本技能默认只交付方案，不创建目录、重命名、移动、删除、去重或声称释放空间。规划不是执行授权；用户另行要求实际操作时，必须由具备适用工具和权限的流程在执行前核对目标、冲突和恢复方式。

## 锁定范围和用途

记录清单是否完整、目标范围、文件系统大小写规则、整理目的和排除项。未知内容、用途、时间或依赖保持未知，不根据扩展名、文件名或目录位置补造。

为每个范围内来源给一个决定：唯一目标、作为依赖组的一部分整体移动，或保留原位并说明原因。一个整体目录映射可以明确覆盖其中所有对象，不必机械拆成每文件一行。解释中重复引用原路径不等于重复分配；判断标准是每个来源只有一个实际决定。

方案至少保留受影响对象的原路径和拟议目标或保留状态。排除项只说明不动，不展开其内部内容。

## 区分内容重复与安全删除

同名、同大小或相近日期只是核查线索，不能证明内容相同。可靠的完整内容比较可以支持“内容相同”，但仍不能单独证明某一路径没有用途。

判断能否安全合并或删除，还要检查引用、备份、发布归档、权限、所有者和保留要求。内容相同但用途不同的副本可以都保留。材料已明确说明逐字比较完成时，可以忠实转述该事实；不要把它误写成自己刚执行了比较。

## 处理目标冲突

同时检查目标中已存在的名称和计划内部的目标唯一性。按材料给出的大小写敏感性比较；未知平台不默认所有系统行为一致。

存在冲突时可以使用描述性重命名、独立子目录或保留原位。没有唯一命名偏好时不强制数字后缀、日期前缀或无空格风格。最终计划不能覆盖现有对象，也不能让两个来源落到大小写等价的同一目标。

## 保持项目依赖

对 HTML 与相对资源、代码项目、素材包等已知依赖，按整体用途保持内部相对布局，或只在有充分映射时整体迁移。不要为了按扩展名分类，把脚本、图片或样式从其依赖项目中拆走。独立参考资料可以按用途另行规划。

## 使用正确的日期

区分拍摄、创建、修改、导入和同步时间。用户要求按拍摄年月时，只使用明确提供或可靠元数据给出的拍摄时间；修改时间不能自动替代。拍摄时间未知的文件可保留原位或进入待确认区域，不编造年月。

## 输出与核对

按用户需要使用表格、清单或目录映射，避免固定长模板。交付前检查每个来源是否只有一个决定、目标是否无冲突、依赖是否保持、排除项是否未触碰、未知是否仍为未知，以及所有动作是否仍明确为计划。
