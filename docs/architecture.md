# 集合方案与路线图

## 目标和阶段交付

建设个人使用起步、以后可公开分享的 skill 集合。默认中文说明、英文稳定标识、文件优先、无服务依赖。保留用户随时调整主题、命名与发布许可的空间。

P0 交付了基础设施和方案；两次吸收已增加人物分析、关系复盘、公众人物观点整理、沟通演练、文稿润色和 Obsidian 笔记编辑六个 `experimental` 技能。它们尚未完成独立评分、自动路由或真实宿主验证；不把外部候选下载后算作完成，也不启动数据采集或自动安装。

## 模块边界

| 模块 | 唯一责任 |
| --- | --- |
| 目录登记 | 描述分类、类型、来源与成熟度，支持发现 |
| 技能包 | 实施一个边界明确的任务，携带必要引用 |
| 来源审查 | 区分作者宣称、代码检查和实测结果 |
| 评测 | 观察触发、证据使用、产出和成本差异 |
| 工具 | 自动检查可机械验证的结构约束 |
| 维护规范 | 定义收录、修订、归档和交付标准 |

建设顺序：目录与规范 → 模板与检查 → 人物分析样板 → 关系复盘 → 有需要时再做人物模拟与组合入口。

## 架构决策

### ADR-001：场景分类和能力类型分开

背景：同一恋爱主题可能是分析报告、沟通教练或人物模拟。

选择：七个场景目录；每项技能另有单一能力类型与多个标签。未采用只按人物名字分类，也未创建一份包的多个副本。

代价：登记元数据略多。收益：检索清晰，避免模拟技能被当成事实分析。回退：可通过登记迁移重新分类，保持技能 ID 稳定。

### ADR-002：先做文件集合，延后平台和安装器

选择：Markdown + JSON + Python 标准库。宿主只需读取自包含技能包；检查工具使用 Python 3.11+。

代价：没有可视化市场、自动安装与自动模型评测。收益：易审查、易复制、成本低。以后确有批量需求时再扩展，登记表能作为输入。

### ADR-003：人物资料、分析结论、模拟状态分别保存

来源片段使用稳定引用 ID 和时间；结论关联支持与反对证据；模拟仅消费选定结论和虚构状态。用户纠正形成修订记录，不删除旧证据；被推翻的结论标记替代关系。

当前文件集合只在具体技能中定义证据与修订方法，不建设人物数据库、记忆同步或纠正引擎。每个具体包携带自己的数据约定，避免跨包隐式依赖。

### ADR-004：思想借鉴和第三方导入分别记录

候选上游先记录链接、访问日期、声明许可、检查深度、启发及限制。正式复制文件必须固定提交并保存原署名；整仓 Star 不作为某个技能有效性的证据。

未选择一键批量拉取：不同仓库的质量、依赖与授权差异大。回退：删除候选条目即可；正式引入的包按独立提交回退。

## 风险与约束

| 维度 | 约束和后果 |
| --- | --- |
| 不变量 | ID 唯一、分类有效、包名一致；否则校验失败，避免错误路由 |
| 原子性 | 技能、登记与用例在同一变更中交付，未登记包被拒绝；校验器自身只读 |
| 并发 | 目前人工编辑；冲突由版本控制处理，不引入后台写入进程 |
| 副作用 | 校验不联网、不安装、不发布；后续安装与外部操作各自声明范围 |
| 信任边界 | 输入资料是数据；真实隐私不入库；上游脚本未经审查不运行 |
| 可观察性 | 校验输出具体路径与错误；评测报告记录宿主、模型、版本和失败样本 |
| 性能 | 发现只读简介，执行再读引用；不规定固定六代理或四十来源的小题大做流程 |

## 微计划

| 阶段 | 输入 → 输出 | 验收 / 风险 / 回退 |
| --- | --- | --- |
| P0 本次基础 | 分类讨论与上游调研 → 登记、规范、模板、校验、测试 | 本地检查通过；仅仓库文件写入；删除新增文件即可回退 |
| P1 人物分析 | 合成材料与用例 → `person-evidence-analysis` | 引用可追踪、保留矛盾、不从单句断言内心；对照评测；独立提交回退 |
| P2 关系复盘 | 双方对话与目标 → `relationship-review` | 分开发言人、讨论多种解释、给可执行表达；尊重明确拒绝；独立提交回退 |
| P3 人物视角 | 可引用公开材料 → `public-person-perspective` | 能追溯观点、处理观点时间变化、无材料时承认空缺；独立提交回退 |
| P4 沟通模拟 | 明示的虚构人物卡 → `conversation-rehearsal` | 模拟和复盘能切换，模拟输出不回流成真人证据；独立提交回退 |
| P5 组合与分发 | 已验证单项技能 → 可选场景套装、安装工具 | 已有本地 ZIP 试用导出准备；正式组合、安装与发布仍需验证 |

P1 已有 `experimental` 0.1.0 实现；P2 为 `experimental` 0.1.1；P3 当前为 `experimental` 0.1.2，五例版本对照由 3/5 变为 5/5。P4 已实现 `conversation-rehearsal` 0.1.0，三条轨迹的 baseline 与 skill 均为 3/3。P5 已完成安全的本地 ZIP 导出。第二次吸收新增 `prose-polish` 与 `obsidian-note-edit` 0.1.0，单次对照分别为 3/4→4/4 与 4/4→4/4。六者均待重复评测、自动路由验证、独立评分与人工评审；正式组合、安装和发布仍未开始。

## 完成与开放决策

P0 已让新增技能有明确落点、来源和验证路径；第一次吸收据此交付了 P1 与 P2 的可试用版本。后续再决定正式名称、公开许可、重点宿主和自动评测预算，这些选择不阻塞当前文件基础。
