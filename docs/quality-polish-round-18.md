# 第十八轮质量打磨：论断证据前向诊断

日期：2026-09-11

## 范围

`claim-evidence-review` 0.1.0 原有四个活动用例，初始对照为无Skill与当前包都4/4，无法说明额外增益。本轮先冻结更难的新题，不修改Skill：部分共享来源、字段级更正、有限日志、聚合反转、材料内指令与链接边界，以及强证据正向控制。

无Skill与0.1.0使用相同的 `gpt-5.6-sol`、`medium`、任务正文和只读隔离环境。Skill臂采用项目级显式调用，硬标准不进入生成提示。六题、两臂各重复三次，共36个有效输出；没有provider error、禁止工具调用、失败重试或排除。

协议经另一个同项目任务复核后，在提交 `2dd75b3753748e0f40181d76fa152667d335e828` 冻结。当前包指纹为 `bfda03a341b9d1b62f2004b7854fca0d4e7712a730a95274e3f9a4b43f7d8e29`。

## 决定

保持 `claim-evidence-review` 0.1.0，不修改Skill、不升版。冻结前约定只有同一机制跨题、跨重复稳定失败才设计候选；当前数字遗漏只在一个拓扑内重复，baseline也出现一次。此时追加规则容易围绕单题过拟合，并进一步放大已经存在的输出成本。

六个冻结题全部加入活动回归，`claim-evidence-review` 从4项增至10项，全仓活动用例从106项增至112项。目录状态继续为 `experimental`，`evidence` 仍为 `null`。

下一批应使用至少两个表面不同的多样本来源图，复测是否稳定漏掉各独立样本的核心分子、分母或前后值。只有跨拓扑复现且候选能在三臂前向回归中改善，才考虑0.1.1。

## 盲评产物事件

18个匿名评审项共108个布尔判断。第一次计分尝试因完成表尚未写入而在读取阶段失败，没有揭盲。原评审任务随后写入既有匿名判断，计分成功。

揭盲后，评审理由又做了一次UTF-8显示兼容重序列化。评审者元数据、108个布尔判断和18个偏好没有改变；排除理由文本的仓库侧规范投影在前后均为 `8c98ddf359148697a0f0d9e8fb7b4fe0022b066a2334f7b3b517a8986efe4261`。原计分结果保留，正式报告使用另存的 `encoding-fixed` 结果。本事件不改变分数，但属于审计链瑕疵，不能写成所有产物在揭盲前一次生成成功。

## 限制与校验

- 全部是合成材料，不是真实研究或私人数据；
- 只验证显式项目条件，不证明隐式路由；
- 显式臂没有 `skillCalls` 遥测，不能单凭配置证明每次实际读取正文；
- 评审者接触过协议和当前Skill，不知道匿名映射，但不是独立人工领域专家；
- 只有单模型、单推理等级和每臂三次；
- 偏好与成本都是描述性结果。

- `python scripts/validate_collection.py`：通过；
- `python -m unittest discover -s tests -v`：68项中67项通过，1项因Windows无符号链接权限跳过。
