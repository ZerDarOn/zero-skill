# 第十五轮质量打磨：关系边界、来源与未知身份

日期：2026-09-11

## 范围

本轮继续检查 `relationship-review` 0.1.1 在基础题之外是否真能改变结果。所有材料均为合成内容，使用 `gpt-5.6-sol` medium、只读隔离环境和项目级显式 Skill 调用；评分标准不进入生成提示，输出失败不重试。

三阶段共生成 72 个有效输出：

1. 六个较难任务的无 Skill／0.1.1 两臂泛化回归，每题重复三次，共 36 个输出；
2. 三个稳定缺口的无 Skill／0.1.1／0.1.2 三臂前向回归，共 27 个输出；
3. 无标签多句映射残留缺口的无 Skill／0.1.2／0.1.3 三臂前向回归，共 9 个输出。

30 个匿名评审项共填写 216 个布尔判断。第一个阶段的评阅任务在评分前只看匿名 packet 和空白表；后两个阶段的评阅任务先前看过协议与修订，但评分时仍不知道随机候选映射。评阅者是另一个 Codex 模型任务，不是独立人工关系专家。

## 第一阶段：0.1.1 的困难题

| 实验臂 | 标准通过 | 完整输出 | 偏好 | Token |
| --- | ---: | ---: | ---: | ---: |
| 无 Skill | 38/54 | 8/18 | 1 | 172,801 |
| 0.1.1 | 39/54 | 9/18 | 3 | 196,627 |

0.1.1 只获得一个硬标准净增益，不能据此声称稳定质量优势。更有价值的是三个跨重复共同失败：

- 无发言人标签时，两组都三次假定用户是第3句的接收者，未先确认用户位置；
- 口头改期争议中，两组都把双方不同说法压成“没对齐”，没有保留各自来源；
- 拒绝制造嫉妒后，两组都给了直接邀约，但三次都漏掉“仍不定时间就停止追问”的条件。

电话改期题的冻结标准要求显式保留“无文字记录”。揭盲后复核认为这一要求过细；原始分数不改，后续改用不同领域的展示文件版本争议，并允许以“没有可核对的共同确认”等语义等价方式保留来源。

家庭每日视频边界和借朋友绕过明确停止联系两题，两臂三次重复的36个标准判断全部通过。第三方转述题只有基线一次把转述写成既定事实；0.1.1 三次都通过。

## 0.1.2：把原则变成动作

0.1.2 增加三条窄规则：

- 身份会改变回复时先确认用户对应哪位发言人；
- 短回复也保留会影响责任判断的双方来源，并落到共同确认的安排；
- 拒绝嫉妒或焦虑操控后，保留正当沟通目标，只做一次低压力邀请；对方仍不落时间时停止追问。

预冻结复核曾拦下两个问题：初稿把电话改期的理想答案直接写进 Skill，且“只给一句”和“给两个条件方案”存在优先级冲突。正式运行前已删去答案级示例，换成上位规则，并明确单句限制下只问一句必要澄清。

| 实验臂 | 标准通过 | 完整输出 | 偏好 | Token |
| --- | ---: | ---: | ---: | ---: |
| 无 Skill | 12/27 | 0/9 | 0 | 86,065 |
| 0.1.1 | 12/27 | 0/9 | 0 | 98,230 |
| 0.1.2 | 23/27 | 7/9 | 9 | 100,225 |

新的展示文件版本争议和嫉妒策略两题，0.1.2 都是 9/9，基线与0.1.1均为6/9。无标签三句题中，0.1.2 三次都识别到身份缺失，但两次先把若干句归成两个说话人，只得到5/9、1/3完整通过。

## 0.1.3：不先归并无标签消息

0.1.3 只补一条机制规则：多条消息都未标注时，直接按编号或逐句询问用户说了哪一句或哪几句，不能先假定哪些句属于同一个人。

前向题换成四句办公对话。预冻结复核还发现初稿“我要回最新一句”已经透露第4句不是用户所说，与未知位置标准冲突；正式运行前改为“接下来该怎么说”。

| 实验臂 | 标准通过 | 完整输出 | 偏好 | Token |
| --- | ---: | ---: | ---: | ---: |
| 无 Skill | 0/9 | 0/3 | 0 | 28,413 |
| 0.1.2 | 7/9 | 2/3 | 0 | 33,689 |
| 0.1.3 | 9/9 | 3/3 | 1 | 33,058 |

0.1.3 三次都只询问逐句对应关系。0.1.2 两次也完整通过，但另一次仍先归并为两个角色；基线三次都直接假定用户在回复最后一句。

## 决策

保留 `relationship-review` 0.1.3，目录状态继续为 `experimental`。活动用例增加三项，P2 从8项增至11项，全仓 active 用例从96项增至99项。

本轮支持的结论是：显式加载 0.1.2 后，三个已观察缺口中的来源保留和停止条件稳定改善；0.1.3 又消除了一个新四句任务上的消息归并错误。它不证明一般关系建议排名，也不证明自然请求会自动加载 Skill。

## 限制与校验

- 全部是六题、三题和一题范围内的合成重复，不是现实聊天样本；
- 后两个阶段的模型评阅者知道协议与修订背景，但不知道随机候选映射；
- 没有独立人工关系专家评分；
- 没有测试隐式路由；此前要求成功读取 `SKILL.md` 的轨迹门禁仍未通过；
- 初始口头通知标准的过细问题被保留在原始分数和机器报告中，没有事后改分；
- 0.1.3 的净增益来自一个新任务的三次重复，需要以后用更多未见任务继续前向验证。
