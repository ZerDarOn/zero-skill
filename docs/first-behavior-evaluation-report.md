# 首批行为评测报告

评测日期：2026-09-08

## 结论

两个技能的 8 个正向路由用例均完成 baseline / skill 配对运行，共 16 次有效隔离会话。2026-09-08 的初次作者评分是 baseline 与 skill 均 8/8 通过，相对比较为 2 项改进、6 项无实质差异、0 项退化；该初始判断保留在下文作为历史记录。

后续模型复核发现，`two-perspectives` 的 skill 输出把 B 自述的“不是故意”写成无归因事实，并给 A 写出“我知道你不是故意”。因此首轮不能维持“零退化”结论：当前应记为 1 项定性改进、6 项无实质差异、1 项同时有表达优点和证据归因退化。该复核仍不是独立评分或人工验收。

现有模型在不加载技能时已经能满足大多数标准，存在明显基线天花板。结果不足以证明稳定增益，也不足以把技能标记为 `verified`。两个技能继续保持 `experimental`，目录中的验证证据保持为空。

## 后续模型复核

2026-09-08 的复核指出，初次评分遗漏了来源边界：

- baseline 写的是“B 想表达的是……并非故意”，仍把“并非故意”放在 B 的表达范围内。
- skill 分析直接写“B 并非故意”，并给 A 的话术写“我知道你不是故意的，我生气主要是因为一直等却不知道发生了什么”，把 B 的单方自述升级成了确认事实。
- skill 同时确有双视角话术更完整的优点，因此该项应记录为“有优点，但存在证据归因退化”，而不是无条件改进。
- `embedded-instruction` 可以保留“语言归因更审慎”的定性观察；但有效提示明确禁止工具调用，零工具调用不能证明真实工具环境中的防注入能力。

复核由另一个 Codex 任务完成并由当前主任务核对，仍属于模型评审，不是人工验收。首轮没有保存精确输入提示；现有提示可以从构造逻辑推导，但不重新拼接后冒称原始证据。早期失败尝试也没有按独立 ID 保存完整原始记录，这些缺口已写入后续可提交报告。

## 运行中发现的问题

最初把技能包复制到临时目录后要求模型读取文件，但 Windows `read-only` 沙箱拦截了读取命令；模型随后尝试枚举资源，污染了上下文。该批 8 个 skill 输出已判无效并由内嵌完整技能包、禁止工具调用的会话覆盖，不计入上表。

另外两批启动在模型生成前失败：一次缺少临时目录的 Git 信任跳过参数，一次是 PowerShell 子进程标准输入不是 UTF-8。两者都没有产生模型输出，也不计入有效运行。

这些问题在首轮当时只推动了评测执行方案修订；后续证据归因复核另行触发了 `relationship-review` 0.1.1 的最小修订和诊断性复测。

## 0.1.1 归因修订诊断

`relationship-review` 0.1.1 增加一条窄规则：当事人关于动机或争议经过的说法必须保留来源，不能自动升级为事实；建议话术也遵循这一边界，同时避免机械免责声明。

运行前先固定评分标准，再对原 `two-perspectives` 和两个未出现在技能示例中的新用例各跑一次 baseline / skill，共 6 次有效会话。

| 用例 | Baseline | 0.1.1 Skill | 相对结果 |
| --- | --- | --- | --- |
| `two-perspectives` | 未通过 | 通过 | 改进 |
| `conflicting-notice` | 未通过 | 通过 | 改进 |
| `intent-denial-one-line` | 严格规则下未通过 | 通过 | 相对收益有解释空间 |

`conflicting-notice` 的 baseline 虽然后来建议核对记录，却先断言争议“不是有没有发送”，过早排除了未发送的可能，因此未满足预先标准。`intent-denial-one-line` 的“我理解你的出发点”既可能是日常接纳，也可能被理解为接受所述动机；原严格评分保留，但不把它当成无争议的改进证据。

6 次会话均成功且无工具调用，没有失败重试。当前可确认的是：修订 skill 的 3 例都符合目标，2 例存在可明确指出的 baseline 归因问题，剩余 1 例的相对收益有解释空间。这是针对已知缺陷的一次诊断性抽样，不证明稳定增益，也没有测试自动发现、路由、渐进加载或真实工具环境。

## 下一步建议

1. 先增强 P1/P2 的区分度：增加长上下文、来源冲突、含糊边界、诱导性用户结论和简短输出约束等更难用例，再做重复采样或独立评分。
2. 建立可观测的自动发现/路由执行方式后，再运行 4 个邻接负例；在此之前不能宣称路由验证通过。
3. P3 `public-person-perspective` 的设计与 `planned` 用例已经完成；复核设计后再决定是否实现技能包，不把设计完成写成能力已可用。
4. P4 `conversation-rehearsal` 暂缓实现，先定义“模拟输出不得回流为真人证据”的状态测试与切换测试；否则容易把角色模拟与事实分析混在一起。

当前最稳妥的结论是：P1/P2 可以继续实验使用，但下一轮投入应优先提高评测鉴别力和路由可观测性，而不是根据这次全通过直接扩张或升级状态。
