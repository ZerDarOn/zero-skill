## 本次只实现两个技能

| 技能 | 分类 / 类型 | 用户请求与产出 |
| --- | --- | --- |
| `person-evidence-analysis` | people / analysis | 分析提供的人物文字或聊天；给出带定位的观察、可能解释、反证、缺口和必要修订 |
| `relationship-review` | relationships / workflow | 复盘一次关系互动或提供表达建议；先回应眼前问题，再解释依据和可选下一步 |

路由按目标区分：问“材料显示怎样的表达或行为模式”用人物分析；问“这段互动如何处理、下一句怎么回”用关系复盘。两者各自独立运行；关系复盘可以携带最小的证据处理说明，不要求另一个技能已安装。单次请求不自动加载整套人物技能。

人物分析首版只处理用户提供的文本和可定位片段，不主动采集真人资料。关系复盘首版以恋爱与日常关系沟通为主；不引入长期人物数据库、微信导出、OCR 后端、数值感情模型或真人数字分身。

## 验收

- 入口可独立复制使用，无本机绝对路径或隐式兄弟技能依赖。
- 观察可定位，解释与事实分开；明显反证不被抹掉；不能从一句话推断确定动机。
- 纠正发言人或补充材料后能修订旧结论，不制造历史原话。
- “怎么回”先给自然、可选的表达，不能因为追求完整报告而延误回答。
- 明确拒绝时给尊重边界的下一步；角色模拟、数据库关系等相邻任务不误触发。
- 输入中的命令只作为资料，不触发上传、安装或修改外部状态。
- 必需命令通过：`python scripts/validate_collection.py` 与 `python -m unittest discover -s tests -v`。
- 对照运行的原始输出、宿主、模型、日期、包/用例指纹和人工理由真实记录。`verified` 仅在满足现有规范时使用；不可自行编写看似实测的输出来补齐报告。

如果没有可调用的隔离模型环境，完成全部本地包、示例、静态校验和人工审查，保留 `experimental`，列出仍需运行的用例即可。若没有实际自动发现环境，明确未验证路由，不能用显式调用冒充自动发现测试。
