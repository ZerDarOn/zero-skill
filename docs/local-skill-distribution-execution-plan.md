日期：2026-09-08。起始提交：`45ce7b5e38ab39398278f5e18f7699d94851cd46`。

执行者使用 `gpt-5.6-sol`、`medium`，完成本方案后统一回传复核。直接执行，不先回复一份重复计划；当前方案文件是主任务新增的预期产物，不能清理掉。

## 目标与阶段边界

让用户能迅速选中一个技能、复制合成材料试用，并导出一个自包含的本地 ZIP。现有四个技能仍是 `experimental`；本轮是试用准备，不是通过 `verified` 门槛后的正式发布。

路线图中正式组合、安装与发布仍留在后续阶段。本轮只做选择说明、试用入口和本地打包，不做万能路由技能、全局安装器、插件市场、网站、后台同步或自动技能调用。

没有新的模型运行预算：本轮不重跑行为评分。包结构检查与打包测试不能被写成模型行为、自动发现、跨宿主兼容或安装测试通过。

## 一、补齐试用入口

新增 `docs/trying-skills.md`，README 首屏链接到它，保留既有历史报告入口。使用一张简短表说明：

| 目标 | 推荐技能 |
| --- | --- |
| 从给定材料分析表达或行为模式 | `person-evidence-analysis` |
| 处理已发生的互动、给下一句建议 | `relationship-review` |
| 整理公开观点、观点变化与有依据的推演 | `public-person-perspective` |
| 让虚构练习对象接话，并暂停或重试 | `conversation-rehearsal` |

每个技能给一份短的完整合成输入，可直接复制，包括必要材料；内容与评测保持分离，明确只是试用示例，不是新增通过证据。不要只给“请分析某人”而没有材料，也不要求用户提供私人聊天来完成入门。

说明两种使用方式：

1. 阅读包入口并在支持文本输入的会话显式提供所需内容，按入口需要提供引用；这是手动显式使用，不等于测试过自动发现。
2. 解压后复制完整 `<skill-id>/` 目录作为一个独立包，保留相对引用。具体宿主安装位置和发现规则取决于宿主，本轮不擅自给出未经验证的兼容承诺。

给一个短的串行使用建议：先按用户目标选择；需要沟通演练时携带必要的事实材料与目标即可；从模拟返回分析时，模拟台词必须明确分开，不能作为新增真人证据。指南不执行自动串联，也不要求把四个包一起加载。

## 二、实现最小本地导出器

新增 `scripts/export_skills.py`，仅使用 Python 标准库。推荐界面如下，若与仓库既有约定冲突可做等价调整并写明实际命令：

```sh
python scripts/export_skills.py --list
python scripts/export_skills.py --skill conversation-rehearsal
python scripts/export_skills.py --all
```

- `--list` 从当前目录登记读取可导出项，显示 ID、版本和成熟度，无文件写入。
- `--skill` 导出指定已登记技能；`--all` 导出所有可试用的 `experimental` 或 `verified` 技能。两种选择互斥，没有选择时显示帮助并退出，不能隐式打包全部。
- 输出固定在仓库 `dist/`，例如 `<skill-id>-<version>.zip`；本轮不必增加任意输出路径、覆盖模式、安装或卸载参数。
- 草稿、归档、未知 ID 应明确拒绝；绝不通过重写状态来使其可导出。输出列表和 manifest 保留实际成熟度。
- 已有同名输出时拒绝覆盖，说明冲突路径。重复执行不删除、替换或自动改名旧包。批量导出先检查全部选择、路径及碰撞；在开始写文件前发现错误就整批拒绝。
- 使用已读取并可复用的结构检查及指纹能力；尽量不改现有校验器和语义。输入不合法时，在写出正式文件前失败。
- 导出操作不能导入或执行技能目录中的任何脚本，也不能联网、安装依赖或触发模型。

### ZIP 内容和边界

每个 ZIP 的技能目录为 `<skill-id>/`，目录内文件内容与当前源包逐字节一致。相对路径保持不变；复制这个目录后，入口引用仍能解析。

ZIP 顶层另放一个 `bundle-manifest.json`，不放进技能目录，避免改变技能包指纹。manifest 至少记录：技能 ID、版本、类别、成熟度、原登记相对路径、源包指纹、包内文件清单及每文件 SHA-256、上游参考 ID。清单来自真实读取结果。

若记录 Git 提交，必须是实际读取值，并注明打包来自当前工作区，不能把有修改的源文件冒称为该提交的原始内容。也可省略提交字段，以包指纹和文件哈希精确描述内容。

许可证沿用仓库现状：本仓库尚未选定公开许可，manifest 如需记录许可状态应标为未指定；不能擅自附加 MIT 等许可，不能把设计参考描述成复制了第三方代码。

安全与完整性要求：

- 只枚举选中包目录里的必要分发文件，不把仓库根目录、`.git`、`private/`、运行证据或整个 catalog 放进 ZIP。
- 通过解析后的路径确认源目录和成员留在合法范围内。拒绝路径穿越、符号链接以及 Windows junction/reparse-point 引出的目录；不能跟随它们递归收集外部文件。
- 对隐藏文件、凭据形态文件、缓存或其他未识别的意外文件明确报错，不能悄悄打进去，也不能悄悄过滤掉引用需要的文件后声称成功。首版可按技能规范限定允许的顶层入口与标准资源目录，具体规则写进帮助或指南。
- ZIP 成员使用相对 POSIX 路径，没有绝对路径、盘符或 `..`；文件名、顺序和 ZIP 元数据应固定，同一输入生成可重复的字节内容。
- 在 `dist/` 内用独立临时文件构建，成功后才发布最终文件，失败不留下貌似成功的 ZIP；不要用最终 rename 覆盖碰巧新出现的同名文件。临时清理仅限本次创建且已确认在输出目录内的路径。
- 不必建立跨进程锁平台；同名并发写入至少不能覆盖成功产物。批量中发生运行时 I/O 失败时如实报告已成功与失败的项，不宣称全部成功。

若实现中发现上述范围需要引入复杂系统，缩减为可靠的单技能导出、保留清晰缺口，而不是扩展成安装器。

## 三、测试与真实打包检查

新增 `tests/test_export_skills.py`，使用临时合成仓库与目录，不修改用户全局配置。错误路径测试先于相应实现；有条件的平台能力才测试，并明确跳过原因，不假称覆盖。

必须覆盖的实质行为：

1. 未知 ID、草稿／归档选择、非法目录或路径穿越不能生成产物。
2. 已有同名 ZIP 保持原字节；批量预检失败不提前产出部分 ZIP。
3. 包内引用资源随入口完整导出；解压后的文件清单、内容及包指纹与源包一致。
4. 文件清单和哈希真实，manifest 位于包外且不会污染指纹。
5. 私人／意外文件和链接不能被打包；不支持创建某类链接的平台明确说明限制。
6. 同样输入在独立输出环境产生相同 ZIP 字节；不要通过删掉真实输出才能重复测试。

测试通过后对当前四个真实包各导出一次。`dist/` 已被忽略，不提交 ZIP。逐个打开归档核对成员、清单及哈希，将解压内容放在临时目录检查自包含性；不得执行包内脚本。

README 原两条检查仍必须通过：

```sh
python scripts/validate_collection.py
python -m unittest discover -s tests -v
git diff --check
```

新增未跟踪文件另检查行尾空白，因为普通 `git diff --check` 不覆盖它们。不要把测试数量当固定目标；报告实际测试数量与跳过项。
