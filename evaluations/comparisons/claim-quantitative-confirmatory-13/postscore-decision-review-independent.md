# 第二十轮揭盲后独立决策复核

## 结论

**决策合理，且冻结门槛未触发。** 应保持 `claim-evidence-review` 0.1.0，不打开或设计 0.1.1 候选；将这三个已冻结的新题加入活动回归集是合理的，但它们应被表述为合成定量保真回归覆盖，而不是对 Skill 普遍优越性或真实研究质量的证明。

未发现会改变门槛结论的计分错误、揭盲映射错误或协议不一致。以下两项属于需要在最终报告中明确保留的非阻塞证据限制：

1. `summary.json` 的状态仍是 `awaiting-human-review`，它是正式盲评完成前的运行汇总快照，不能单独作为揭盲后最终状态；正式质量结论应以完成的匿名评阅、揭盲映射及 `review-result-blind-review-completed-independent.json` 为准。
2. 评阅者是 `model-assisted-independent-codex-task`。这证明了评阅在另一个 Codex 任务中按匿名候选完成，但不等于独立人工或领域专家复核；对“评阅者未查看揭盲键”的保证主要来自流程约束和评阅声明，而不是能够从最终文件单独证明的访问隔离。

## 独立重算

我从 `blind-review-completed-independent.json` 的逐候选布尔值出发，再用 `blind-review-key.json` 映射实验臂，没有采用 `summary.json` 的质量总分作为计算输入。结果如下：

| 实验臂 | 通过标准 | 完整输出 | 偏好次数 |
| --- | ---: | ---: | ---: |
| baseline | 44/45 | 14/15 | 1 |
| ours 0.1.0 | 45/45 | 15/15 | 7 |
| 持平 | — | — | 7 |

共 15 组匿名比较、每组两名候选、每名候选三条标准，即每臂 45 条标准判断。唯一失败项是 `equal-rate-different-denominators-r2` 中揭盲后属于 baseline 的候选 A：它写出两批样本量和共同的 25%，但没有同时保留硬标准要求的 `5/20` 与 `125/500`。评分器生成的汇总与上述独立重算完全一致。

偏好映射也一致：ours 获得 7 次、baseline 获得 1 次，另有 7 次持平。偏好优势多数发生在双方都通过全部硬标准的输出之间，常由表达是否更直接、是否加入非必要推导等细微差异决定，因此它可以作为辅助信号，但不应替代冻结的核心遗漏门槛。

## 核心遗漏与门槛

冻结协议指定的核心标准分别是：更正与缺失分母题的标准 1、相同比例不同分母题的标准 2、严格表格题的标准 2。按揭盲映射逐题重算为：

| 题型 | baseline 核心遗漏 | ours 核心遗漏 |
| --- | ---: | ---: |
| `corrected-and-missing-denominators` | 0/5 | 0/5 |
| `equal-rate-different-denominators` | 1/5 | 0/5 |
| `strict-table-two-batches` | 0/5 | 0/5 |

候选触发条件是一个合取门槛：必须存在至少两个题型，且在这些题型中 ours **各自**达到 `>=2/5` 核心遗漏，同时 baseline 在每个对应题型均为 `<=1/5`。本轮 ours 在三个题型都是 `0/5`，连一个题型的第一条件都未达到，因此门槛明确不触发；baseline 是否满足上限不会改变这个结论。跨第十八、十九轮的揭盲后 `4:2` 探索性观察按冻结协议不并入本轮门槛。

- `results.json` 的 SHA-256 为 `061d17ee0bffb218e537ef8b518ba67f4bdf79983da5c9b937510d975a721bdd`，与 `summary.json` 一致。
- 完成评阅文件的 SHA-256 为 `eb99153e7df14e36f8bd782460f190ca25d8ef969bc6792024b7be8f663200fe`，与评分结果文件记录的评阅哈希一致。
- 原始结果共有 30 行，两个实验臂各 15 行，全部执行成功，无 provider error 或禁用工具使用。两臂均为 `gpt-5.6-sol`、`medium`、只读、禁网、隔离工作目录；ours 使用冻结哈希对应的项目级显式 Skill 包。

## Token、成本与延迟边界

以下数值由 `results.json` 的 30 行原始度量独立汇总，与 `summary.json` 一致：

| 指标 | baseline | ours 0.1.0 | ours 相对变化 |
| --- | ---: | ---: | ---: |
| 总 token | 147,025 | 160,611 | +13,586（+9.24%） |
| prompt token | 143,420 | 155,930 | +12,510（+8.72%） |
| completion token | 3,605 | 4,681 | +1,076（+29.85%） |
| cached token | 106,880 | 127,232 | +20,352（+19.04%） |
| 总成本 | 0.261012 | 0.2593048 | -0.0017072（-0.65%） |
| 单次中位延迟 | 10,834 ms | 11,059 ms | +225 ms（+2.08%） |

ours 的 token 使用更高，尤其是 completion token；这与显式加载 Skill 后提供更完整说明的方向一致，但本轮不能证明因果。ours 的记录成本反而略低，主要结果不能解读为 Skill 更省钱：两臂 cached token 构成不同，单轮调用顺序和服务端缓存计价足以影响小额成本差。延迟只是在每臂 15 次、并发 4 的一次运行中比较中位数，225 ms 的差异没有置信区间或重复运行支持，不能据此断言稳定性能回归。30 次运行总评测时长约 90 秒也不是两臂各自的串行耗时。

## 决策建议

- **保持 0.1.0：合理。** ours 没有出现核心遗漏，也没有触发冻结协议预注册的变更条件。
- **不设计候选：合理且必要。** 仅凭 45/45 对 44/45、7 次对 1 次偏好，越过预注册门槛设计 0.1.1 会构成揭盲后改规则。
- **三题加入活动回归：合理。** 三题分别覆盖原始分母规模、分母更正与未知分母、严格短表中的双批次数值和因果限制；本轮也实际捕获了一次 baseline 原始分数遗漏，说明其具备回归辨别价值。加入后应保留冻结题面和计数规则，并继续将其描述为合成回归，不标记为真实模型、联网研究或独立人工领域验证。

综上，本轮证据支持“0.1.0 在这三个冻结合成表面上未复现此前担忧的核心定量遗漏”，不支持更宽泛的“Skill 已被普遍验证”或“稳定优于无 Skill”。在这个边界内，保持版本、不开候选并纳入活动回归是与协议一致的决策。
