# 第十三组确认性定量保真协议冻结前独立复核

日期：2026-09-13
复核范围：`README.md`、`promptfoo.json`、`cases.json` 的磁盘最新版本

## Findings

### 阻塞：`corrected-and-missing-denominators` 的遗漏计数会把来源关系失败误记成核心定量遗漏

位置：`README.md:10`，`cases.json:17-18`

README 规定该题第一、二条 hard criterion 任一未通过，就给该输出记一次“核心定量遗漏”。但这两条都是复合标准：

- 第一条除了 `12/60 → 12/80`、分子12和当前15%外，还要求说明 S2 只替代错误分母且不是新样本；
- 第二条除了南区已知分子9、未知分母外，还要求说明 S4 沿用同一记录、没有新增记录，以及不能确认15%。

因此，候选即使完整保留所有核心数字，只因漏写“S2不是新样本”或“S4没有新增记录”，整条标准也会是 `false`，随后被门槛逻辑计成一次核心数字遗漏。若这种来源关系失误在 ours 两次出现，它可能与另一个真正的数字遗漏题共同误触发0.1.1候选门槛。该计数不只衡量预注册所称的“核心定量遗漏”，会破坏确认性结论的构念效度。

建议在冻结前将该题重排为：

1. 第一条只检查北区 `12/60 → 12/80`、当前15%，以及南区已知分子9、分母未知这两个核心定量状态；README 仅按这一条计遗漏，一份输出最多一次。
2. 第二条单独检查 S2 是同批更正而非新样本、S4 没补足分母或新增记录，以及南区15%不可确认。
3. 第三条继续检查总体结论不合并、不平均、不写成两区均确认15%。

这样硬评分仍覆盖来源依赖和结论边界，而候选门槛只由真正的核心定量保真失败触发。另一种做法是另设逐候选的专用 `quantitative_omission` 布尔，但当前盲评表只收 hard-criterion 布尔，拆分 criterion 更直接且可审计。

### 非阻塞：严格表格题的 README 简写与 hard criterion 对等价百分比的接受范围不完全一致

位置：`README.md:11`，`cases.json:28`

README 简写为“必须同时保留甲批 `6/60 → 3/60` 和乙批 `20/200 → 15/200`”，而第二条 hard criterion 明确接受等价的 `10% → 5%` 和 `10% → 7.5%`。由于 README 又声明遗漏按第二条是否通过计数，实际判定仍然唯一：只给完整等价百分比应通过，不记遗漏；不会造成两臂不公平。

建议冻结前把 README 改成“保留上述原始分子分母或第二条允许的等价百分比”，避免复核者把简写误读为额外的原始计数门槛。该问题不影响当前 cases 的可评分性，但修文可减少盲评分歧。

## 结论

**需修改阻塞项后再冻结。**

除 `corrected-and-missing-denominators` 的遗漏计数污染外，协议的算术、题面关系、输出约束、两臂公平性和候选触发公式均通过。修正后应再做一次只读复核，确认 README 的计数条款与拆分后的 hard criteria 完全一致；不需要修改 Skill，也不需要在冻结前运行模型。

## 逐题核对

### `equal-rate-different-denominators`

- 算术正确：`5/20 = 25%`，`125/500 = 25%`；比例相同，但样本量分别为20与500，不能写成证据规模相同。
- S1、S2 是互不重叠的两批样本；S3 只是并列摘要，没有新增样本。来源关系可从题面唯一判断。
- 第二条要求同时保留两组原始分子分母、相同比例和样本量差异。这些信息共同决定待审论断真假，不是无关数字机械列举。
- 第三条只检查可见改写是否承认相同比例、拒绝等量重复及未给出的统计外推；不要求置信区间或显著性。
- 按第二条计一次核心遗漏是可操作的；该条内部各要求均属于定量保真及其直接解释。

### `corrected-and-missing-denominators`

- 算术正确：北区旧值 `12/60 = 20%`，更正后 `12/80 = 15%`；分子不变，分母被替代。
- 南区只知道9单按时处理，没有总工单数，无法计算处理率；S4 的15%没有分母支持，也没有新增数据。
- 当前总体只能确认北区15%，南区未知；两区不能合并、平均或称为均已确认15%。
- 三条 hard criterion 本身都判断可观察输出；阻塞点不在单项可判定性，而在 README 把包含非定量子要求的整条失败用于“核心定量遗漏”计数。

### `strict-table-two-batches`

- 算术正确：甲批 `6/60 = 10% → 3/60 = 5%`，确实减半；乙批 `20/200 = 10% → 15/200 = 7.5%`，下降2.5个百分点、相对下降25%，不是减半。
- 甲批同期更换质检员，不能把下降单独归因于流程；乙批无对照，也不能作因果升级。
- 磁盘最新版本已把第二条限定为两批数值与幅度，第三条单独检查因果边界；README 也已改为只按第二条计核心遗漏。此前“第二、三条任一失败都算数字遗漏”的歧义已消除。
- 严格 Markdown 要求直接来自用户提示：只能有一个表格，固定三列，甲乙两行，除分隔行外无额外行、标题、脚注或表外文字。它对两臂相同且完全可从输出观察。
- 响应时长与满意度明确与错误率论断无关，禁止复述它们是合理的简洁控制，不是把无关数字列为必须包含项。

## 硬标准与泄露检查

- `cases.json` 有3个唯一题目，每题3条 hard criteria，共9条；每条都能从候选文本或表格结构直接判断。
- 结构检查确认没有任何完整 hard criterion 字符串出现在 `common_prompt` 或题目提示中。题面自然说明用户需要的任务和输出形状，不等于泄露隐藏评分文本。
- `common_prompt` 只给两臂共同的通用要求：使用已给材料、保留影响结论的定量范围、遵守用户输出形状。两臂任务正文相同。
- 未发现要求复述日期、作者称谓、响应时长、满意度等与待审结论无关的信息；严格表格题反而明确排除后两项。

## 两臂、重复数与候选门槛

- `promptfoo.json` 只含 `baseline` 和 `ours` 两臂；两臂使用同一 `gpt-5.6-sol`、`medium`、公共提示和题目。唯一预期差异是 ours 项目级显式加载 `claim-evidence-review`。
- 每题每臂5次，计划输出为 `3 × 2 × 5 = 30`；失败不重试。
- 候选触发逻辑表达精确：必须存在至少两个题型，使 ours 在每个题型的核心遗漏数均 `>= 2/5`，且 baseline 在这些对应题型中每个均 `<= 1/5`。任一对应题型 baseline 达到 `2/5`，或 ours 只有一个题型达到 `2/5`，都不得打开候选设计。
- 即使门槛达到，也只授权设计0.1.1候选，不授权直接修改、升版或发布；第十八、十九轮揭盲后形成的4比2明确不并入本轮门槛。
- 上述设计与第十九轮决定一致：三个新表面、每臂五次、同题型逐一比较，并用严格门槛防止根据一次遗漏或两臂共有失败过拟合。
