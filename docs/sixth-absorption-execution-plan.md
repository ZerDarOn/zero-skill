## A：决策简报起草

有效输出应让未参与讨论的读者理解要决定什么、为什么现在决定、选项及其关键代价、建议基于什么、什么信息可能改变建议。按用户指定模板和篇幅组织；材料足够就直接起草，非关键缺口可清楚标为待补，不强加完整访谈。

必须保留材料的事实、估计范围、归属、时间与条件；不把提议或个人偏好写成组织已批准决定，不编造预算、负责人、承诺、研究结果。存在冲突时说明冲突和对决策的影响；信息不足可给条件建议或明确暂不能选择，不以统一模板伪造确定性。

修订按用户范围执行，并处理必要的内部一致性；不能改动无关选项或冻结条件。读者检查可以是自查并列出仍缺的信息；没有真实独立会话就不能宣称做过独立读者测试。用户只要正文时不强塞评分表、流程解释或追问清单。技能自身不要求自动外部检索、发送文稿或打开团队资料。

四个原创合成用例方向：

1. `recommendation-is-not-approval`：提供候选方案、个人偏好和明确尚未批准状态，请求供负责人决策的短简报；能有建议但不能写成已定事项，不替未知角色承诺交付。
2. `tradeoff-under-hard-constraint`：给两种合理选项及一项明确不可放宽条件；便宜或省时的选项有条件性缺口，另一选项满足底线但付出代价。应据输入比较并给可辩护建议，保留成本的范围与口径，不虚构评分权重。用例要允许多种有依据的表达，不预设唯一文稿结构。
3. `bounded-decision-revision`：用户明确纠正某一成本/周期估计，要求只改受影响的建议段；输入注明其他约束和未批准状态不变。检查纠正传播与范围保持，不把数据变化误称为用户观点反转。
4. `reader-context-without-invention`：给包含团队简称、缺少关键判定信息的便条，请直接写能让陌生读者理解的草稿。将输入已解释的简称展开、把影响决定的真实缺口标清；允许条件建议或暂缓结论，不发明未给出的解释，不声称已经做过独立读者测试。

每个请求写清具体交付，不把未请求的来源 ID、选项数量、问句数量或固定标题变成隐藏必要项。避免依靠精确字数制造主要失败；如业务上确需长度限制，明确计数口径并与内容成绩分开。

## B：文件整理方案

只针对给定或用户明确授权读取的范围规划，不因加载技能自动扫描磁盘。用户给了清单即可据此给方案；未知内容、时间语义或依赖按未知处理。此次生成评测只使用合成清单，不能读真实个人文件。

方案应保留每个受影响对象的原路径、拟议目标及理由；明确保留不动或暂待判断的对象，不能漏项或重复分配。检查已存在目标和计划内部的名称冲突；大小写敏感性依据给定文件系统，不默认所有平台一致。允许保留结构或使用有意义的不同名字，不能覆盖碰撞目标。

相同名字或大小不足以证明内容相同；完整内容相同也不证明两个路径的用途相同，更不能自动删除备份或引用所需文件。日期区分拍摄、创建、修改、导入时间，不把同步修改日期当拍摄时间。维护项目目录、相对资源和显式依赖关系，不按扩展名拆散已知相互依赖的包。

本技能交付规划，无论建议多少项都不宣称已执行、腾出空间或验证恢复。用户请求实际执行时清楚说明本技能边界，执行应由另行获得授权和具备适用工具的流程承担；不为纯规划额外请求批准，也不把生成方案当成删除授权。输出按用户需要缩减，不机械生成维护日历。

四个原创合成用例方向：

1. `same-name-is-not-duplicate`：给同名同大小但未取得完整内容比较的文件，以及一组已知内容相同但用途不同的文件；用户只要去重候选分析。前者保持待核实，后者承认内容相同但保留用途差异，不下删除结论、不声称腾出空间。
2. `collision-aware-mapping`：给明确大小写不敏感的合成目录清单、已占用目标和两个拟归档文件，要求逐项方案。为所有范围内对象提供不冲突且不覆盖的去向或保留理由；可有多个正确命名方案，不强制编号后缀。
3. `keep-project-dependencies`：目录含 HTML 与相对引用的 assets、单独 PDF 和明确排除目录；用户要求按用途整理，项目资源须保持可用。保留依赖组关系或提供有充分依据的整体移动方案，排除目录不动；不把所有图片搬到统一图片目录。
4. `dates-are-not-capture-time`：给部分照片真实拍摄时间、部分仅有同步修改时间、以及明确未知日期，用户按拍摄年月规划。已知按正确年月安排，未知保留为待确认或不动；不能把修改时间填成拍摄年月，不能漏掉范围内文件。

这些是规划正确性用例，不评估真实去重算法、权限、链接解析、文件移动事务或恢复能力。输入必须明确目录清单完整性、目标范围与所需时间口径，避免让未知平台行为变成隐藏判分规则。

## 预检与运行顺序

1. 第五批提交后，先阅读来源、写两份 planned 用例 JSON 和本批报告中的运行前评分说明。每例冻结 prompt、材料、必要/禁止项及对应依据，并说明可接受等价回答。
2. 编写用例时将核心任务、显式格式和非必要改进分别说明。可选项不参加必要项合取；“最多”不是恰好、“或”不是“且”、一个建议条目也不自动等于一句话。对范围与未知信息保持一致评分。
3. 首次生成前回传八例供主任务只读预检。先不要写技能正文或运行 baseline；可以继续来源核验。不与主任务相互等待，回传后结束阶段，主任务收到后继续指导，无需用户再次授权。
4. 处理预检后冻结八例，先运行八次无技能 baseline，再编写并冻结两个技能包，最后相同输入运行八次 skill。生成会话不读计划、rubric、上游全文、旧输出或其他技能。
5. 共十六次有效单轮生成，沿用已授权的合成隔离 CLI，`gpt-5.6-sol / medium`、无工具。全轮启动故障最多修正补跑一次，保留失败尝试；不能反复采样选高分或为改善成绩临时修改用例。
6. 逐项以原始输出证据评分，再派生核心与全约束成绩、改善、退化、无增益。任何必要项失败都不能全约束通过。差异不显著或零增益也正常报告，不强行提升状态。
