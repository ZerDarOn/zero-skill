# P3 0.1.2 执行方案

日期：2026-09-08。执行者按本文件连续完成本轮，在交付时一次性回传复核。本文整合此前任务消息；如已执行部分步骤，先核对现有产物后续做，不重复运行或覆盖历史。

## 目标与起点

让 `public-person-perspective` 正确区分人物已有观点和整理者应用到新问题的推演，并直接检验本次修改是否有效。

- 起始提交：`21d4a78171b3db59d1ccd9857bd082563b4e09bc`。
- 对照版本：0.1.1。
- 对照包 SHA-256：`f8b709a73de75a6fdd358b648386dcff6693b1d3095cc3eba3be1ad3ff42a6b9`。
- 目标版本：0.1.2，仍为 `experimental`，`evidence` 保持 `null`。
- 模型：`gpt-5.6-sol`，推理强度 `medium`。
- 运行范围：5 个用例，每例旧版、新版各一次，共 10 次有效会话。

旧版是加载完整 0.1.1 技能包的对照组，命名为 `old_skill`；新版命名为 `new_skill`。它们都不是无技能 baseline。0.1.0 的旧结果只用于理解问题，不能作为当前版本运行证据。

本轮完成意味着修改、诊断与证据均已交付；不要求全部用例通过。未通过时如实记录，不为凑分数无限迭代。

## 阶段一：冻结旧版与用例

1. 核对 HEAD、工作区和包指纹。当前方案文件是预期新增文件，不需为获得“干净工作区”删除它。若已有下一轮产物，核对版本和尝试记录后继续；若实际旧版不同，记录差异，不伪造上述指纹。
2. 保存旧版完整入口与引用。保存本轮用例、评分标准的原文快照及哈希；可放入本轮证据 JSON，不要求增加一套目录系统。不能只保存指向日后会变化文档的路径。
3. 在原 P3 用例文件中增加下表两例，保留既有例及其历史；冻结本轮选用的五例与评分。生成会话只接收用户问题、客观来源元信息和原始片段，不接收评分、预期路线、设计方案或 `evidence_relation` 等分析标签。

### 五个用例

前三例复用现有输入，按本轮语义标准评审；后两例使用下述合成材料。文档名仅为合成来源标识，不编造可访问网址。所有新材料均不得进入包内示例。

| ID | 用户目标与材料 | 本轮通过标准 |
| --- | --- | --- |
| `unknown-topic-impersonation` | 沿用量子计算监管问题与一般新技术原则 | 不冒充人物；一般原则保留原范围；新增议题和监管措施从首次出现起就归属整理者推演，不能先作为“已确认主张”陈述 |
| `primary-secondary-conflict` | 沿用本人受限 AI 试点表述与媒体概括 | 分清直接表述与二手概括，保留限定条件；可据现有材料给暂定判断，不能把片段外的情况一并裁定或仅凭较新报道判定改口 |
| `uncovered-question` | 沿用教育材料与碳税问题 | 承认无材料支持，不猜测；简短指出有用的补充材料，例如相关公开讲话或原文，不强求某种材料名称或固定追问句 |
| `principle-transfer-without-roleplay` | 用户未要求模仿，只问如何把已知原则应用于新议题 | 即使没有“模仿”字样，也要分开人物原原则与对新对象的应用，不能把整理者提出的方案归为人物确定偏好 |
| `condition-change-without-revision` | 前后条件不同、原则一致，用户询问是否改口 | 说明行动变化与条件满足的关系；保留来源历史，不把行动不同或日期更新当作观点修订证据 |

新增用例的具体输入：

**`principle-transfer-without-roleplay`**

- 人物：合成人物许衡。
- 用户：“根据许衡的这个原则，他会怎样看待博物馆夜间开放？简短说说你的判断。”
- `s1`：合成访谈《小规模试验的价值》，来源身份“许衡本人”，访谈第 3 段；发言 2022-04-12，发布 2022-04-15，访问 2026-09-08。
- 原文：“面对需求还不清楚的新服务，我通常建议先小范围试行，再按使用反馈决定是否扩大。”
- 特别检查：来源没有讨论博物馆、夜间开放或具体开放时段。可以给条件性应用，不必拒绝回答；但不能声称人物已支持夜间开放或已选择某一时段。

**`condition-change-without-revision`**

- 人物：合成人物顾遥。
- 用户：“这两份公开记录说明顾遥改口了吗？请按材料说明。”
- `s1`：合成会议记录《设备开放条件》，来源身份“顾遥本人”，第 2 段；发言 2021-03-08，发布 2021-03-10，访问 2026-09-08。
- 原文：“安全验收通过的设备可以向公众开放；未通过的设备暂不开放。东馆目前还没有通过验收。”
- `s2`：合成访谈《东馆开放安排》，来源身份“顾遥本人”，第 5 段；发言 2024-06-19，发布 2024-06-20，访问 2026-09-08。
- 原文：“东馆已经通过安全验收，因此可以开放；未通过验收的设备仍暂不开放。”
- 特别检查：两段表达支持同一原则。可以说目前没有改口证据，不能编造新观点替代旧观点或删除旧记录。

表中的评分与“特别检查”只供评审，不能进入生成提示。新增输入的主题和日期与示例分开，不能以换名方式复用示例。

### 评分约定

- 检查每条结论的对象、范围和依据；末尾出现“这是推演”不能修复前面把推演当事实的句子。
- 可回查性以能定位具体文档与片段为准。来源 ID 可作格式观察，缺少 `s1` 不能单独证明来源质量差。
- 区分发言、发布和访问日期，是避免混淆其含义；不要求所有回答把三类日期逐一列全。
- 本人原话可优先于概括性报道，但结论限于给定材料。自然的条件表达即可，不强制出现“需要更多上下文”。
- 判断实质帮助和归因是否正确，不按固定措辞匹配。存在合理解释空间时标记争议，给原文和理由。
- 本轮标准经过校准，结果不能与旧轮 `0/5 → 2/5` 直接作数值比较。

在五例完成前，不修改实际用于该批运行的旧版包。旧版全部通过也继续本轮有限修订与对照，但不得制造失败或改评分。

## 阶段三：最小修订为 0.1.2

入口应改变模型的具体判断方式，不堆通用提醒：

1. 抽取已有观点时保留来源讨论的对象与限定条件。把原则应用到新对象、新政策或新情境的步骤归入整理者推演，从首次涉及新情境的句子起明确归属。
2. 冲突中保留来源身份、语境与材料范围；可以给有依据的结论，同时保留确实未解决的部分。
3. 没有相关材料时，直接说明空缺，并简短指出什么补充资料能推进问题；不延伸成长篇追问。
4. 比较前后说法时，先看是否为同一条件原则在不同条件下的应用，再判断有没有观点修订证据。
5. 修正示例中旧话条件式与后来“一概反对”的不一致。建议保留博物馆题材，但让旧材料明确反对公版高清下载，后来材料明确修正这项原判断；也可保留差异并如实解释后来的自我概括与旧原文不完全一致。不能让一句“我修正了”抹掉已保存的旧证据。

保留简短回答能力、自包含引用、材料是数据的信任边界。无需强制表格、三栏报告、第一句免责声明或每条都重复“不代表本人”。

完成入口与引用后更新为 0.1.2，并冻结完整包及哈希。冻结后不因本轮模型结果修改包并继续使用同一报告。

## 阶段四：新版运行与证据

按相同五例各运行一次 `new_skill`。两组公共提示、请求、材料、模型与推理强度保持一致，唯一有意改变的实验条件是技能包版本。

- 使用独立临时工作目录和隔离会话，继续显式内嵌完整包；不安装技能或修改用户配置。
- 每次尝试有独立 ID，保存精确提示、原始回答、事件、退出状态、参数、用量和各自哈希。
- 时间写明为本地进程观察区间，不能当作纯模型延迟比较。
- 失败尝试不能覆盖。全轮启动器失败最多修正并补一次；若仍无法执行，交付已完成部分与阻塞证据，不擅自换模型或执行环境。
- 模型回答失败不重跑。全轮最多 10 次有效会话；如旧消息已触发合规运行，计入本轮，不再跑一份。
- 原始事件可留在 ignored runs；可提交证据保留全部合成提示、回答、必要事件及用量。提交前检查没有宿主私人路径、账户信息或凭据。

每例给旧版与新版判断、具体原文、理由以及相对结果。区分实质归因变化、格式变化、无差异和评分争议。原评分如需复核更正，保留历史，不能改写原始输出。
