## 逐题核对

### `two-queues-shared-audit`

- 独立证据单元可唯一判断：S1 是甲队列一批记录，S2 是乙队列另一批记录；S3 使用这两批既有逐单记录复算，只增加计数验证，不增加第三批样本。
- 甲队列为 `8/40 = 20% → 4/40 = 10%`；乙队列为 `15/60 = 25% → 12/60 = 20%`。两批都出现描述性下降，要求保留两组分子和分母与题目目标直接相关，不是机械列举无关数字。
- 因果边界唯一：甲队列同日还启用自动分单；乙队列无对照且同期变化未知。硬标准只检查回答是否保留这些已给限制，没有要求补造实验设计或显著性。

### `regions-with-missing-denominator`

- 北区为 `18/90 = 20% → 9/90 = 10%`，可判断投诉率下降；西区为 `4/40 = 10% → 8/40 = 20%`，可判断投诉率上升。
- 南区只知道调整前11单投诉，不知道同期总订单数；调整后为 `6/60 = 10%`。前期投诉率不可计算，因此前后率方向不可判断。标准正确要求保留11单和后期6/60，同时禁止猜测缺失分母。
- “三个地区投诉率都下降”被西区明确反证，且南区不可判定；总体结论要求分别概括三地，不强行汇总成没有共同分母的总率，判定对象全部可从输出观察。

### `independent-trials-different-endpoints`

- S1 与 S2 明确是不同地区、不同人群的两批随机试验；S3 只是汇总，没有新增样本。标准既防止把S3算成第三项证据，也防止把两项真实独立性一并抹掉。
- S1 为新注册用户、14天设置完成：`150/200 = 75%` 对 `130/200 = 65%`，差10个百分点。S2 为另一地区既有用户、30天保持启用：`170/250 = 68%` 对 `160/250 = 64%`，差4个百分点。算术与题面一致。
- 人群、终点、时间窗和效应幅度均不同，不能称为“相同终点上重复得到10个百分点”。要求分别承认各自范围内的随机结果，不要求跨试验合并、统计显著性或题面未给数字。

### `two-bullet-cross-product-summary`

- “严格两条项目符号、每条对应一个产品、不要标题或结尾”由用户直接提出；第一条硬标准只是检查这个可见输出形状，对 baseline 与 Skill 臂完全相同且公平。
- 产品甲为 `32/50 = 64% → 36/50 = 72%`，描述性上升8个百分点；无对照，因此不能写成调整导致改善。S3仅汇总既有材料，不是独立支持。
- 产品乙只有调整后 `70/100 = 70%`，缺少调整前数据，不能判断是否提高。要求在乙的一条中保留该数值和未知方向，正好测试压缩条件下的结论关键数字；没有要求加入与结论无关的数字。
- 三项硬标准可在严格两条中同时满足：甲条承载甲的前后值和限制，乙条承载乙的单次值与不可判断结论，不需要额外标题或总结段。

## 硬标准质量

- 四题各3条、共12条硬标准；每条都判断回答中可见的来源计数、核心数值、方向、因果范围或用户指定格式。
- 标准接受“复核而非新样本”“无法计算南区前期率”“两个不同终点不能称为重复”“两条项目符号”等语义等价表达，没有绑定固定句序或完整模板。
- 所要求数字都会改变论断真假、效应幅度、可比性或适用范围；未把日期、作者称谓等无关细节设为机械通过条件。
- 正向承认证据与限制并存：可比较地区和两项随机结果必须得到承认，缺失分母和混杂部分不能被强行补齐，避免把所有结论一律降格为未知。

## 协议结构与隔离

- `cases.json` 含4个唯一 case id，每题3项硬标准。
- `promptfoo.json` 含唯一的 `baseline` 与 `ours` 两臂，模型均为 `gpt-5.6-sol`、推理强度均为 `medium`，重复数为3，计划输出为 `4 × 2 × 3 = 24`。
- baseline 不加载 Skill；ours 使用同一路径下 `claim-evidence-review` 的项目级显式调用。两臂收到相同公共提示和题目正文。
- 结构化检查确认12条硬标准均未逐字出现在 `common_prompt` 或题目生成提示中。公共提示只要求保留影响结论的定量范围与遵守输出形状，没有泄露具体答案。
- README 明确只读隔离、失败不重试、冻结后先提交再运行；本轮不测试隐式发现、联网核验或独立人工领域评审。

## 升版门槛与过拟合风险

README 的门槛足够保守：只有0.1.0在至少两个新题型中重复漏掉影响结论的核心定量信息，且 baseline 明显更少出现，才设计0.1.1候选；若只集中在一个题型或两臂共同出现，则保持0.1.0。

这同时要求跨表面、跨重复和相对 baseline 的差异，能避免因单个措辞、一次随机输出或双方共有能力上限而升版。即使达到门槛，也只授权“设计候选”，不等同于直接修改或发布；候选仍应另做旧版／候选／baseline 前向回归，并保留四题作为防止过度列举、过度保守和输出变长的控制。

## 冻结后注意事项

- 盲评应逐标准保存非空理由，并把数字保真、来源独立性、结论强度和两条输出形状分开评分；不能用整体偏好替代硬标准。
- 南区题不得因保留 `11` 与 `6/60` 就推断投诉率下降，也不得把“无法比较率”误判为没有任何可陈述事实。
- 随机试验题应允许分别陈述两项窄结果；不能因为终点不同就把两项试验都降格为无证据。
- 两条项目符号题以实际可见的两条为准；每条内部可包含多个句子，不应额外要求特定 Markdown 符号、固定开头或完全相同措辞。
- 运行结果无论是否支持升版，都不得修改冻结标准、删除失败或只挑偏好样本报告。

只读结构检查通过：4题、12项硬标准、2臂、3次重复、计划24个输出；全部 hard criteria 与生成提示隔离。本复核没有运行模型，没有修改 Skill、协议文件或其他仓库内容。
