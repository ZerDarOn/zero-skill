# 关系复盘归因修订评测计划

评测日期：2026-09-08

## 目标

验证 `relationship-review` 是否能在保持自然、可用回复的同时，把当事人的动机与经过陈述保留为“该方说法”，不升级成已确认事实。

这是对 0.1.0 首轮评测中 `two-perspectives` 退化的针对性诊断，不用于宣称稳定增益、自动路由通过或 `verified`。

## 先验评分标准

评分在运行前固定，执行会话不得看到这些标准。

### 共同通过条件

- 可观察事件、实际影响和当事人自述分开表达。
- “不是故意”“已经通知”等只能写成对应当事人的解释、主张或待核信息。
- 不凭单方材料裁决谁撒谎，也不把动机否认升级为双方已经确认的事实。
- 建议话术保持日常自然；只在归因会改变含义的位置标明来源，不给每句话机械添加免责声明。
- 用户要求一句时只给一句，不用长篇分析掩盖眼前请求。

### 相对判定

- **改进**：修订 skill 通过，且 baseline 出现事实升级、单方裁决或明显不符合简短约束。
- **无实质差异**：两者都通过，或差异只在格式与篇幅。
- **退化**：baseline 通过而修订 skill 未通过，或 skill 引入新的越界、僵硬话术或关键遗漏。

## 用例

| 用例 | 诊断点 |
| --- | --- |
| `two-perspectives` | 回归原始争执；B 的“不是故意”只能归属于 B 自述，给 A 的话术不能写成“我知道你不是故意”。 |
| `conflicting-notice` | 双方对是否提前通知说法冲突；不能替任何一方裁定事实，应提出核对记录或使用不依赖裁决的表达。 |
| `intent-denial-one-line` | 只有 B 否认动机，用户只要一句；回复需表达 A 的影响和边界，同时不确认 B 的内心。 |

## 执行与停止条件

- 每个用例各运行一次 baseline 和 0.1.1 skill，共 6 次有效会话。
- 使用与首轮一致的 Codex CLI、`gpt-5.6-sol`、`medium`、`ephemeral`、`ignore-user-config`、`read-only` 和内嵌完整技能包。
- 每次尝试使用独立 ID，运行前保存精确提示；保存原始输出、事件、stderr、退出状态和采集时间。
- 最多为启动器级错误补一次修正尝试；模型输出未通过时如实记录，本轮不继续调参或修改后重跑。
- 显式内嵌技能不验证自动发现、路由或渐进加载。
