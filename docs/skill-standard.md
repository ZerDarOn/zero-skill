# 技能标准 v0.1

## 发现和包装

ID 使用小写字母、数字和单连字符，最长 63 字符。唯一包路径为 `skills/<category>/<id>/SKILL.md`。一个包处理一个明确的用户任务；内部步骤不必各自变成技能。

本仓库入口 frontmatter 采用一个刻意简单的 YAML 子集：

```yaml
---
name: person-evidence-analysis
description: "根据用户提供的对话或文字分析人物表达与行为，列出证据和可能解释；不用于角色扮演。"
---
```

只接受这两个键，description 是单行 JSON 双引号字符串（同时是合法 YAML）。这是本集合的编写约定，校验器不是通用 YAML 解析器。宿主元数据如有实际需要，独立放在包内 `agents/` 并针对宿主验证。

入口保持精简；引用文件写明何时读。包内 Markdown 相对链接不能逃出包目录，不能使用本机绝对路径。依赖脚本、可选工具及不可用时的降级在入口说明。没有跨宿主实测时只称“文件格式可读取”，不称“完全兼容”。

## 登记与成熟度

每项记录：ID、分类、能力类型、版本、路径、标签、上游 ID、用例路径和评测证据路径。

- `draft`：正在设计；结构正确也不等于可用。
- `experimental`：入口、素材及人工审查完成，可以试用；尚未证明比无技能更好。
- `verified`：有本版本的对照运行和人工判定；结论仅适用于记录的宿主、模型和用例。
- `archived`：保留来源和历史，不作为默认推荐。

`evaluation` 可指向合成用例 JSON；`evidence` 可指向脱敏后的评测记录 JSON。verified 必须同时提供二者。记录格式见评测模板和 `evaluations/README.md`。

## 人物资料约定（后续技能采用）

每份材料记录：`source_id`、材料类型、获取方式、时间范围、可引用片段及其定位。真人使用别名；只有任务必要时才保留其他个人信息。

每条结论区分：观察事实、解释假设、材料缺口。解释关联支持和反对证据；写清适用情境。出现反证时修订，不强行让全部素材支持既有画像。可靠程度用理由表达，不伪造概率。

修订记录包含：结论 ID、旧值、新值、变更原因、来源、日期。用户自述和用户对他人的推断分别记录。模拟产生的对话不得成为真人证据。

只凭头像、面相或少量用语，不推断敏感身份、精神疾病或确定的内心动机。MBTI、星座等可用于明示的娱乐设定，不当作现实人物结论的证据。

## 来源审查

候选登记的 `review_level` 使用 `readme-reviewed` 或 `entrypoint-reviewed`，并通过 `evidence_url` 指向实际阅读材料。检查更多内容时更新记录；不把成功打开 URL 写成完成全文代码审查。

正式复制第三方文件前，逐项记录具体提交、文件清单、许可文本、所需署名、素材的独立权利与本地修改。公开仓库不自动等于可任意复用。上游称“本地存储”时，还需单独检查模型、遥测和网络请求的数据去向。

本地技能只借鉴设计，没有复制第三方指令；三方对照可在 `evaluations/fixtures/upstreams/` 保存固定提交的未修改文件，但须连同原许可证、署名、逐文件哈希、用途和未包含范围一起登记，且不作为本地技能安装或登记。公开发布前由维护者选定本仓库许可。
