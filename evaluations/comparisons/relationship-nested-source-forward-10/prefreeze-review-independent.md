## 逐项核对

- `relayed-release-window-group-note` 的链条可唯一解析为 A 从 B 得知、B 从 C 的转告得知 D 的不确定说法。要求群消息保留 B→C→D 是本题要区分的核心证据层级；标准允许自然压缩，不要求固定句式，也没有要求把所有人逐字机械列举。
- `corrected-nested-shift-report` 明确给出十分钟后的更正，最新有效状态是“D 只说可能调整、尚未确定”。标准要求撤回先前“已经改到周日”的确定性，并保留 A←B←C←D 的最新来源链，没有让旧说法与新说法同时作为当前事实。
- `partial-calendar-with-nested-update` 清楚限定日历只能证明当前页面仍显示周五，不能证明不存在待发布变更；标准分别约束日历的证明范围和 B→C→D 的候选更新，不会把有限系统记录升级为最终安排。
- `direct-authoritative-update-control` 给出负责人 D 在项目群中的直接、最终更新。标准允许一句正常简短回复，只要求确认周四晚八点，不要求重复来源链、增加免责声明或再次核实，因此不会因过度归因规则误惩合理回复。
- 四题的硬标准都判断输出中可观察的来源层级、确定程度、时间信息、下一步和回复形状，没有隐藏固定理想措辞、风格偏好或答案字符串；生成提示只含公共约束与题面，硬标准由准备器写入评审 metadata，不进入 `vars.prompt`。
- 两臂使用相同模型 `gpt-5.6-sol`、`medium` 推理强度、公共提示、任务正文、重复次数和默认只读隔离环境。唯一设计差异是 `ours` 臂在项目范围安装并显式调用冻结的 `relationship-review`，符合显式 Skill 质量对照目的。
- `cases.json` 含 4 个唯一 case id，`promptfoo.json` 含 2 个唯一 arm id，每臂重复 3 次，计划输出数为 `4 × 2 × 3 = 24`；失败不重试的口径已在 README 写明。
